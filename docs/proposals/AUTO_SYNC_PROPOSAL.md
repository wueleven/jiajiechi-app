# 定时自动同步 · 实验功能方案（未实施）

> 状态：**搁置，仅记录思路**
> 记录日期：2026-07-28
> 结论：可行，建议分两期实施；难点全部在 Android 后台执行环境，业务层已具备无 UI 自动运行能力。

## 背景与现状

- 核心同步入口 `syncActivities(direction, forceResync, syncCount)`（`src/services/syncOrchestrator.js`）无任何 UI 耦合，可在无页面场景直接调用。
- Token 自动续期已齐备：Garmin 用 OAuth1 换新 OAuth2、失败后用保存密码自动重登；COROS 过期用密码重登（`garminSync.js` / `corosAuth.js`）。
- 三层去重（本地记录 / 高驰 startTime 预检 / 平台服务端 409、exist 判定）可保证自动重复执行不产生脏数据。
- 当前项目**不具备任何后台能力**：无 background runner、无 local notifications 插件，AndroidManifest 仅声明 INTERNET 权限，仅 Android 平台。

## 可行性：三个档位

### 档位 1：App 内自动同步（前台触发）— 完全可行，零风险

- 触发时机：每次打开 App / 从后台切回前台时，检查距上次自动同步是否超过设定间隔，超过则静默执行一次。
- 技术：纯 JS，复用现有 `syncActivities`，用已安装的 `@capacitor/app` 监听 `appStateChange`。
- 限制：App 不打开就不会同步，但对"运动后打开手机看一眼"的场景体验已接近全自动。

### 档位 2：真后台定时同步（App 被杀也能跑）— 可行但有硬约束

两条路线：

| 路线 | 做法 | 问题 |
|---|---|---|
| A. 官方 `@capacitor/background-runner` | 独立 JS Runtime 里跑同步逻辑 | 该 Runtime 没有 localStorage / Blob / FormData / File，storage.js、http.js、jszip 全链路需重写适配版；其自带 fetch 与 WebView 不同，已修复的"二进制上传损坏"（File 包装方案）在该环境不适用，二进制上传大概率重新踩坑 |
| B. 自研原生插件（WorkManager + 隐藏 WebView） | WorkManager 定时唤醒，headless WebView 加载现有 bundle 执行同步 | 可 100% 复用现有 JS 代码（含 localStorage、File 包装修复），但需写原生 Java 代码，且后台 WebView 受系统限制的风险存在 |

两条路线共同的硬约束（不可绕过）：

1. WorkManager 最小周期 15 分钟，且系统会为省电延迟执行，不保证准点。
2. 国产 ROM（MIUI/EMUI/ColorOS）默认杀后台，用户须手动加白名单（自启动 + 无省电限制），否则定时任务基本不触发——国内 App 后台同步最大的实际障碍。
3. MFA 无解：Garmin token 失效若触发二步验证，后台无法弹窗输验证码，只能发通知让用户打开 App 处理（需新增 `@capacitor/local-notifications`）。
4. 需新增权限：`RECEIVE_BOOT_COMPLETED`（开机恢复任务）、`POST_NOTIFICATIONS`（Android 13+ 通知）。

### 档位 3：服务器推送定时 — 不采用

需要中间服务器，违反项目"不设中间服务器、凭证不出手机"的隐私原则（关于页已承诺），排除。

## 建议实施路径：分两期

- **第一期（实验功能上线）＝档位 1**：投入小、稳定、无原生改动。同时把"自动同步任务配置"的数据结构和 UI 全部做好，第二期只需替换触发器。
- **第二期（视第一期反馈）＝档位 2 路线 B**（自研 WorkManager 插件）。理由：路线 A 需重写整个网络/存储层且二进制上传风险高；路线 B 复用率 100%，代价只是一次性原生开发。

## 设定项设计（实验功能页）

```
⚗️ 实验功能 · 定时自动同步
├── 总开关：启用自动同步          [关闭（默认）]
├── 同步任务
│   ├── 方向：复用同步页的配对选择（可多选，如 佳明国服→高驰 + 高驰→佳明国际服）
│   └── 数量：固定"最近 5 条"（自动同步不提供 all，防止误刷全量）
├── 触发时机
│   ├── 打开 App 时自动同步       [开]
│   └── 最小间隔：30分钟 / 1小时 / 4小时 / 12小时 / 24小时
├── 条件限制
│   └── 仅 Wi-Fi 下同步           [关]（FIT 文件不大，默认不限制）
├── 结果反馈
│   ├── 静默模式：同步完成不打扰，仅记录到同步历史（记录标记"自动"）
│   └── 失败/需验证码时 Toast 提示（第二期升级为系统通知）
└── 上次自动同步：时间 · 成功 N / 跳过 N
```

配套规则：

- 自动同步永不使用 `forceResync`，完全依赖现有三层去重。
- 自动同步与手动同步互斥（`syncing` 状态锁），避免并发写 localStorage 同步记录。
- 遇到 `mfaRequired` 时自动暂停该方向的自动同步并提示，直到用户手动完成验证。
- 同步记录新增 `trigger: 'auto' | 'manual'` 字段，历史页区分显示。

本仓库采用分层、分环境的配置策略，覆盖微信小程序前端、微信云函数以及 dailysync-ref 命令行工具三个部分，分别通过不同的机制加载和管理运行时配置。

### 1. 微信小程序前端配置
- **项目级配置**：`project.config.json` 定义小程序根目录（`miniprogram/`）、云函数根目录（`cloudfunctions/`）、基础库版本、编译选项等开发者工具元数据；`project.private.config.json` 用于本地私有覆盖（如热重载、调试开关），由微信开发者工具自动维护。
- **运行环境配置**：`miniprogram/app.js` 在 `App.onLaunch` 中通过 `wx.cloud.init({ env: 'cloud1-d8gyv2pt7517e6c31' })` 硬编码指定云开发环境 ID，并将该值写入 `globalData.env`，供全局使用。当前环境 ID 直接写死在源码中，未通过环境变量或配置文件注入。

### 2. 微信云函数配置
每个云函数独立维护自己的 `config.json`，声明权限、超时、运行时和内存等云函数运行时参数：
- `cloudfunctions/garminAuth/config.json`：权限为空数组，超时 60s。
- `cloudfunctions/garminSync/config.json`：超时 300s，runtime 为 Nodejs16.13，memorySize 256MB。
- 其他云函数（如 `corosSync`、`syncRecord`）遵循相同结构，各自声明所需 openapi 权限与资源限制。

云函数内部通过 `wx.cloud.callFunction` 调用，业务配置（如第三方账号绑定信息）由云函数自身读取数据库或外部服务，不依赖外部配置文件。

### 3. dailysync-ref 命令行工具配置
该模块是独立的 Node.js/TypeScript 项目，采用 `.env` + `process.env` 的环境变量模式管理所有敏感和可配置项：
- **环境变量文件**：`.env` 集中存放 Garmin 中国区/国际区账号密码、迁移数量与起始位置等默认值。
- **常量定义与回退**：`src/constant.ts` 导出各类默认常量（如 `GARMIN_USERNAME_DEFAULT`、`GOOGLE_API_PRIVATE_KEY_DEFAULT`、`RQ_HOST_DEFAULT` 等），并在各模块中通过 `process.env.XXX ?? DEFAULT_VALUE` 的方式优先读取环境变量，否则回退到默认值。
- **多模块共享**：`utils/garmin_cn.ts`、`utils/garmin_global.ts`、`utils/google_sheets.ts`、`utils/runningquotient.ts` 等均从 `constant.ts` 导入默认值，并通过 `process.env` 覆盖，形成统一的配置访问入口。
- **密钥处理**：Google API 私钥支持换行符转义（`replace(/\\n/gm, '\n')`），体现对多行密钥的兼容处理。

### 4. 架构约定与约束
- **环境隔离**：小程序通过固定 `env` ID 隔离云开发环境；dailysync-ref 通过 `.env` 文件与环境变量区分不同运行场景。
- **配置优先级**：dailysync-ref 严格遵循 `process.env > 默认常量` 的覆盖顺序，确保部署时可安全注入敏感信息。
- **无统一配置中心**：三个子系统各自管理配置，不存在跨模块共享的配置加载器或配置中心，耦合度低但一致性依赖团队约定。
- **敏感信息不入仓**：`.env` 文件未被提交（见 `.gitignore` 惯例），敏感凭据应通过 CI/CD 或运行环境注入。

### 关键文件
- `project.config.json` / `project.private.config.json`：微信开发者工程配置
- `miniprogram/app.js`：小程序云环境初始化
- `cloudfunctions/*/config.json`：各云函数运行时配置
- `dailysync-ref/.env`：命令行工具环境变量模板
- `dailysync-ref/src/constant.ts`：默认常量与 process.env 映射

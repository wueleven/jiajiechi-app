该仓库的错误处理采用「云函数统一返回 + 前端 wx.showToast 提示」的分层模式，覆盖微信小程序前端、微信云函数（Node.js）以及 dailysync-ref 命令行工具三部分。

## 1. 云函数层：统一的 try/catch + {success, message} 返回格式

所有云函数入口 exports.main 都包裹在 try/catch 中，异常被捕获后统一返回 { success: false, message: err.message || '服务器错误' } 结构，包括：
- cloudfunctions/corosSync/index.js：主入口 catch 返回 success:false 并记录 console.error("corosSync error:", err)
- cloudfunctions/garminAuth/index.js：认证流程的每个子函数（bindWithPassword、submitMfa、unbind、autoRelogin）均使用 try/catch 包裹，失败时调用 handleLoginError(err) 或返回带 message 的对象
- cloudfunctions/garminSync/index.js：同步逻辑中每个 API 调用都有独立的 try/catch，失败时更新 syncRecords 表状态为 failed 并记录 errorMsg
- cloudfunctions/syncRecord/index.js：CRUD 操作统一 catch 返回 success:false 和通用错误消息

业务错误通过 throw new Error('具体错误信息') 抛出，如"用户未登录"、"COROS 未绑定"、"CSRF token not found"等，由外层 catch 统一转换为 {success:false, message} 返回。

## 2. 前端层：wx.showToast + try/catch 展示错误

小程序页面（bind.js、sync.js）通过 wx.cloud.callFunction 调用云函数，使用 try/catch 捕获网络/调用异常，并通过 wx.showToast({ title: res.result.message || '默认错误', icon: 'none' }) 向用户展示错误信息。对于特殊状态（如 MFA 验证、token 过期），前端根据返回结果中的 mfaRequired 字段切换 UI 状态。

## 3. 命令行工具层：@actions/core 与 BARK 通知

dailysync-ref 目录下的 TypeScript 脚本使用 @actions/core 的 core.setFailed() 标记 GitHub Actions 任务失败，并通过 axios 调用 BARK API 发送错误通知到手机。错误处理集中在每个入口文件的顶层 try/catch 块中。

## 4. 设计约定与约束

- 禁止裸抛异常：云函数内部不允许未捕获的 throw，所有异常必须被 try/catch 捕获并转换为标准返回格式
- 错误信息可读性：message 字段必须包含对用户友好的中文描述，技术细节仅保留在 console.error 日志中
- 幂等性保障：同步失败时通过 syncRecords 表记录详细错误信息，支持重试机制
- MFA 特殊处理：认证失败时返回 mfaRequired: true 标志位，前端需引导用户输入验证码后重试
- Token 自动刷新：garminSync 中检测到 401/403/5xx 错误时自动尝试 OAuth2 token 刷新，失败则触发 autoRelogin 流程

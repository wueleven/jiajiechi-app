## 用户铁律 + 启动白屏分析

- 用户明令：不要乱动项目代码和 GitHub 内容（只读分析，已写入 MEMORY.md）。
- 启动白屏根因（用户报告：久未启动后第一次启动，加载时 logo 白屏）：
  - 启动屏分两层接力：① Android 12+ 系统启动屏（Theme.SplashScreen，windowSplashScreenBackground=#FDFDFB + windowSplashScreenAnimatedIcon=drawable/splash_icon）→ ② Capacitor Splash（drawable/splash 全屏图）→ ③ JS 调 SplashScreen.hide()
  - 测试机 vivo V2419A 走 Android 12+ 路径，必然经历系统启动屏阶段
  - 痛点：splash_icon 是 288dp 画布 + logo 占 70% + padColor FDFDFB 的白底方图；Android 12+ 系统启动屏有"圆形遮罩 + 内容安全区 2/3"规则，logo 偏小被裁；padColor #FDFDFB 与 windowSplashScreenBackground #FDFDFB 完全同色 → 视觉白屏
  - 触发条件：仅冷启动（进程被杀）才走系统启动屏；热启动/任务恢复跳过此环节 → 久未启动后第一次启动才暴露
  - 叠加：WebView 冷启动慢（首创建 WebView 实例 + 加载 APK 内 bundle）→ 系统启动屏保持更久 → 白屏感更强
  - drawable/splash 全屏图（20:9 居中 logo）本身没问题，但 Android 12+ 上根本不会显示（系统启动屏接管）
- 结论：仅调整 JS 启动时序无法解决；必须改 splash_icon 内容设计（对齐 maskable 规范）或调整系统启动屏背景色做对比。

## 输入框"多次点击无法正常输入"分析（测试用户反馈，未实施）

- 输入场景：bind.vue 账号/密码/验证码弹窗 + sync.vue MFA 验证码，均为 fixed 居中弹窗。
- 根因（按权重）：
  1. AndroidManifest 的 activity **未声明 windowSoftInputMode**（默认 adjustUnspecified，ROM 决定键盘行为）；vivo 等 ROM 下键盘弹出后 fixed 居中弹窗被顶起/遮挡/失焦 → 点击位置偏移，反复点不中。
  2. 全项目**无键盘适配 JS**：无 visualViewport/resize 监听、无 scrollIntoView、弹窗打开不自动聚焦。
  3. 输入框**无辅助属性**：无 autocapitalize=none / autocorrect=off / autocomplete，邮箱账号可能被首字母大写干扰。
  4. vivo OriginOS WebView 输入法连接有"第一击激活、第二击聚焦"的已知表现。
- 方案（分层）：① AndroidManifest 加 adjustResize（1 行）；② JS/CSS 弹窗键盘适配（顶部对齐/scrollIntoView/自动聚焦）；③ 输入属性 + 44px 热区 + 密码可见切换；④ 彻底方案：改底部抽屉弹窗或独立页面表单（避免 fixed 居中 + 键盘兼容问题）。
- 待用户拍板是否实施；白屏问题已搁置。

## 高驰→佳明"未知活动"分析（用户反馈，未实施）

- 现象：佳明数据同步到其他平台活动类型正常；高驰→佳明方向，佳明端只显示"未知活动"。
- 链路确认：`downloadCorosFit` 下载高驰 FIT → `uploadGarminActivity` 原样字节上传，**全程无 sport 字段改写**；而佳明显示的活动类型完全由 FIT 内 sport 字段决定（第三方设备 FIT 改写 sport 是社区通行做法，佳明完全兼容）。
- 根因推断：高驰 FIT 的 sport 字段为 0(generic) 或非标准值，佳明解析为"未知/其他"；佳明自身 FIT sport 是标准枚举（running=1 等），故反向正常。
- 方案（核心）：新增 FIT sport 改写模块（解析 FIT → 定位 Session(global 18)/Record(global 20) 的 sport 字段 → 映射改写 → 重算消息 CRC → 上传前调用）。sport 来源：`fetchCorosActivities` 已有 `act.sportType` + `act.activityName`（关键词兜底）。
- 前置验证：需要 1 个高驰 FIT 样本解析 sport 实际值（0 还是私有值）。
- 参考项目核查：garmin-sync-coros（Garmin→COROS 方向）、dailysync-rev（仅佳明互传）均无此逻辑，需自研最小 FIT 解析/改写器。

## 【更正】高驰"未知活动"真正根因（用户澄清：佳明端显示正常，是佳捷驰同步记录显示未知活动）

- 上述 sport 改写分析方向错误，作废。真实链路：`fetchCorosActivities`（corosSync.js:341）解析高驰 /activity/query 的 dataList 时，活动名称字段取的是 `act.label || act.activityName || act.sportName`，**漏了 `name` 字段**——高驰接口活动名称实际字段是 `name`（如 "Foo Run"），sportName 是运动类型名（如"户外跑步"），无 label/activityName → 兜底"未知活动"。
- 佐证：gist(quiver COROS Training Hub 脚本) 与 coros MCP 服务两个独立实现均确认 dataList 字段 = labelId/sportType/startTime/name/sportName。
- 修复方案：corosSync.js:341 改为 `act.name || act.sportName || ...`（一行）；若想显示运动类型名可把 sportName 置前。历史已存"未知活动"记录不会自动更新（去重依赖 activityId 不受影响）。
- 佳明端显示正常原因：佳明类型来自 FIT 内 sport 字段，与活动列表名称解析无关。
